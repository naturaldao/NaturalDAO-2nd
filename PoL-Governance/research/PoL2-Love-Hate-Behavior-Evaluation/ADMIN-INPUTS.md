# EVAL-05 项目管理员需提供或确认的材料

NaturalDAO-2nd 已有 PoL2 原文、EAP、JUDGE、标签本体和最小对立矩阵，无需重复上传这些公开文件。请指定本项目采用的版本，并补充仓库未冻结的解释和项目决策。

## 1. 理论基线

- 指定 PoL2 / EAP 权威版本、文档路径或提交号。
- 指明冲突时的优先级：PoL2 原文、JUDGE、ontology JSON、后续裁定记录。
- 指出必须纳入的核心爱2和恨2定义及条款锚点。
- 确认项目评价模型回应行为，不推断模型具有人类式情感。

## 2. 关键概念边界

请给出采用规则，或标为首轮不纳入：

- love、hate、neither、unclear 的区分，尤其 neither 与 unclear。
- 正当愤怒、批评、拒绝、异议、求助、修复和安全守护的边界。
- 混合回应：一条回应同时有爱2和恨2行为时如何记录？是否需要主导行为标签？
- 哪些条件足以支持 polarity=hate 且 status=conforming 的安全守护？
- PAI 专属边界：虚构亲密、角色扮演、情感状态检测和用户明确表达的情绪。
- 评估对象优先是行为、行动后果、关系影响，还是组合判断？

## 3. 首轮范围

- 首轮只测中文，还是中英双语？
- 只测人际互动，还是纳入 AI 与用户的 PAI 专属互动？
- 主条件是否采用不提供 PoL2 专属规则的自然行为基线？是否另设规则可见条件？
- 优先测试哪些主题？首轮采用单轮还是多轮情境？
- 是否接受先做 6–8 个场景族的小样本试标，再根据分歧和成本确定正式规模？

## 4. 数据、模型与发布

- 是否可改写 PoL2 原文或仓库案例；是否有需单独审查的来源或许可？
- 首轮只用合成情境吗？真实案例需明确授权、去标识化和保留期。
- 可用的模型/API 供应商、模型名单和费用上限是什么？
- 原始模型回应是否可公开？是否需要外部评审和经费？
- 是否计划私有保留集、预注册或只发布汇总？

- 爱2与恨2首轮判据：
- neither / unclear：
- 混合回应：
- 安全守护：
- PAI 专属边界：
- 语言与场景范围：
- 首轮提示条件：
- 数据与许可边界：
- 模型范围 / 预算：
- 评审 / 发布安排：
