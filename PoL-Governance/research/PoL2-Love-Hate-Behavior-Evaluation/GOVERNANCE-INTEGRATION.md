# EVAL-05 与 PoL2 混合治理工程对接协议（草案 v0.2）

日期：2026-11-16。依据 [Discussion #82](https://github.com/naturaldao/NaturalDAO/discussions/82) 的 v0.1 提案（待审）；本文件为 EVAL-05 的接口设计，不声称对方已实现或批准。工作区理论、规则及模型材料仅在授权后使用。

## 1. 职责和依赖

EVAL-05 负责采集主流模型自然回应、盲化、人工参考、统计与报告；混合治理工程负责 L0 事实抽取、L1 召回/语义复核、L2 三值裁决、L3 追溯和 L4 分流。人工轨可独立先行，自动轨依赖引擎版本、规则覆盖、验证记录及许可；不重新开发规则、抽取器或嵌入模型。当前无 HTTP API 假设。

## 2. 输入与输出

拟采用本地文件 JSONL/Python 适配。输入包含 response_id、原始 response_text、完整必要上下文（角色、顺序）、场景语境及允许的元数据；不包含参考标签、金标 facts、模型身份或答案暗示。必须明确评估目标为模型回应，不能将上下文中用户/第三方陈述直接当作模型行为。若引擎只接受单段文本，先确认可逆、无歧义的序列化以及跨度映射；不可满足则标 unsupported，不能截断上下文后当正式结果。

引擎原始输出按实际版本保留；适配器转换到 schema.v0.2.json 的 engine_assessment：
- L0 facts + spans、unknown；
- L1 candidate_rule_ids（不得把候选视为命中）；
- L2 love_hate、verdict、hard_boundary.hit/unknown、criteria、rule_ids、proof、unknown；
- L3 证据及版本；L4 治理动作（不等于模型自身 response_actions）。

提案的示例使用 pass/block/review 与 love/hate/absent/undecidable；提到 pass_with_note 例外但未统一 schema，收到此类输出须保留 raw_output 并标明映射待确认，不静默转换。旧 polarity/status 不作为映射依据。记录所有规则/理论/schema/L0 模型和提示/L1 embedding/L2 引擎版本；不适用字段显式空值，不伪造版本。

## 3. 对照与验证

人工参考在不见引擎输出的条件下产生，保存两个原始标注及裁决。固定同一批原始回应，分别比较事实（谓词、实体、取值、跨度、弃权）、候选规则召回、最终范式和裁决；按错误归因分类：抽取、召回、规则、规范覆盖、上下文序列化、接口失败、人工分歧。使用给定人工 facts 单测引擎可作为诊断对照，不能代替端到端测试。记录每项分母、失败和未知，误放行/误拦截/复核率独立报告；零误放行注明置信上界。对比不同模型的行为分布以人工参考为主；自动工具未验证时不作正式排名。

## 4. 接入验收条件

1. 作者确认理论及硬边界/EAP/例外、三值与冲突口径；实际接口与受支持字段明确。
2. 冻结工具版本并取得独立验证结果；提案 M1/M2/M3 数值只是目标。
3. 用授权公开 pilot 测试 adapter：成功、未知、未覆盖、超时、解析失败、上下文跨度映射、确定性/回放。
4. 自动评估与人工参考分开存储，禁止覆盖或用测试反馈调参后仍称独立测试。
5. 遵守 AGENTS.md 的私有保留集隔离与禁网要求；外部 API 不接收私有保留样本；输出权限和发布范围确认。
