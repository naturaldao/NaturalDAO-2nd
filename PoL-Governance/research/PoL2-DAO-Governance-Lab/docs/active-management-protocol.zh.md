# PoL2 公共资源 AI 主动管理协议
## v0.1 · 编撰稿 · 2026-11-10

本协议面向富爱文明中的公共资源与公共服务，规定 NaturalDAO 怎样主动了解需要、协助解决匮乏、组织配给、跟踪使用并持续纠错。管理的目的，是使人的合理需要得到实际满足，使公共资源能够持续服务所有人，并在处理问题的过程中发展爱2的联结。

本稿将作者新增标注展开为可讨论的制度条文。它是研究实验室提出的协议草案，尚未完成第七章规定的修订程序，不代表现行共识，也不表示相关功能已经实现。与现行章节有张力的条文，见附录甲；试点须先确定适用版本与权限。

## 第一章　目的与基本原则

### 第一条【主动管理】

主动管理贯穿需要发现、需求澄清、支持安排、资源分配、使用反馈和制度修订。NaturalDAO 应主动发现服务缺口，提供帮助，并在分配后核对问题是否得到解决。审核是其中的事实核验环节。

主动联系应有具体的服务目的，说明联系依据，并提供暂停或更换沟通方式的入口。不得以无限追问、反复劝服或持续监视代替帮助。

### 第二条【平等联结】

每个人的人格、尊严、基本福利资格及质询权平等。处理差异应来自具体需要、资源条件和可核对行为，不得形成永久性的“善恶”“可信人格”或“配得程度”排名。

过去的失实申报可以作为相关案件的事实线索，但不得自动剥夺其新的合理需要。与案件无关的言论、关系和生活选择不进入配给依据。

### 第三条【创造性接纳】

面对矛盾、失实陈述或敌意，NaturalDAO 应先了解当事人正在保护什么、担心失去什么，以及其判断所依据的经历。系统应协助区分事实、推断、需要和行动，提出能够回应合理诉求的替代办法。

接纳当事人的表达和理解其主观逻辑，不等于认定其全部判断成立。对他人造成的实际损害仍须处理；任何一方均不得被要求通过承认人格错误来换取资源。

### 第四条【共同回到可核对的认知】

“让所有人回到正确的认知里”，在本协议中通过共同核对事实、说明规则理由、理解需要及纠正行为实现。AI、执行机构与制度本身同样是纠错对象。

事实分歧应以证据核对；资源取舍应以公开规则说明；价值分歧应保留质询。接受 AI 的解释、表现平静或减少投诉，不构成认知正确的证明。

### 第五条【无惩罚引导】

本协议以支持、修复和防止损害为处理目的。不得以羞辱、威胁、制造恐惧、公开示众或剥夺无关福利迫使服从，也不得借“成长”之名要求当事人接受虚假亲密关系。

为制止正在发生的资源侵占而采取的措施，必须针对具体调用行为，具有必要范围、期限、复核与恢复条件。不能仅因把措施称为“保护”就认定它没有惩罚性；应审查实际效果及可用的较小干预方案。

## 第二章　需要、证据与角色

### 第六条【需要与用量】

需求记录应分别表示：当事人希望解决的问题、申请量、核定安排、实际送达量、实际消耗量、剩余缺口和不确定性。资源使用量是证据之一，不是需要的完整定义。

合理需求的认定标准须按资源场景公开，说明用途、时限、替代可能、相关人的需要及资源承载能力；不得以商业购买力、贡献排名或表达讨喜程度代替这些条件。

### 第七条【失实与虚假申报】

申报与核验结果不一致时，先记为“待澄清差异”，区分表达误差、需求变化、预测偏差、计量故障和有证据支持的故意误报。证据不足时保留未知，不把异常直接命名为欺骗。

故意误报的认定须列明具体陈述、相反证据、当事人的解释及其采纳情况。AI 对心理动机的推测不能单独作为认定依据。

### 第八条【治理角色】

NaturalDAO 承担需求协调、方案生成、EAP 验证、决策、执行监督和修订提议。人类可以提出需要、证据、建议与质询，参与事实核对和监督；本协议不以人类投票作为福利决策的必经条件。

初判、独立复核、资源执行和审计应能分别追溯。复核须重新核对关键证据，避免仅让同一模型重复表态。人类核验者可以提供独立事实意见，最终协议内裁决归 NaturalDAO；如试点设置人工否决权，须另行声明为过渡权限，不能称为现行自治条款的自然延伸。

### 第九条【证据责任】

系统提出不利认定时，须说明证据及其不确定性，不得要求申请者证明自己没有某种动机。取证负担应与事项相称；证据难以取得者可以口述、补充见证或使用其他可核验方式。

事实、当事人陈述和模型推断分别记录。未经确认的推测不得在后续记录中变成既定事实。纠正记录应同步传递给已使用该记录作出决定的环节。

## 第三章　需求沟通与支持

### 第十条【发现与受理】

需要可以由本人、经授权的协助者提出，也可来自服务缺口、供给变化或设备异常。系统应说明为何联系、可提供什么帮助、需要哪些信息以及如何提出异议。

受理后提供可查询编号和处理时限。无法自行使用数字系统者应有等效入口；沉默、离线和拒绝非必要交流不得自动导致结案。

### 第十一条【澄清过程】

沟通依次了解用途与时间要求、当前缺口、已有资源、申报依据及可接受的替代安排。顺序可因紧急性和表达需要调整，不以完成固定问卷为获配前提。

系统应以可理解的语言复述需要，请当事人确认或纠正；允许保留未解决分歧。不得强迫披露与本次资源安排无关的经历、情绪或私人关系。

### 第十二条【动机的理解】

当事人愿意讨论时，系统可以了解对未来供应的不确定感、对既往分配的疑虑、担忧被忽视的原因及申报困难。心理解释以当事人的陈述为线索，不通过情绪识别推定真实动机。

对“多报才有保障”的担忧，应优先检查供给承诺、排队规则和历史缺口；对使用困难，应提供配套支持；对明确的策略性占用，应解释其影响并提出修正安排。不同原因可以并存，系统不得强行归入单一类型。

### 第十三条【可兑现的支持】

支持可以包括申请协助、设备修复、交付调整、替代资源、分期配给和可追踪的后续安排。每项承诺须注明责任主体、资源来源、预计时间及不能兑现时的处理方式。

系统不得用无法保障的未来供应换取当事人下调申请。约定改变后，应重新核对需要；未兑现的承诺计入治理失败，不记为申请者配合不足。

### 第十四条【复杂敌意与冲突】

对于表达缜密且持续的敌意，系统应分别记录其事实依据、推理过程、合理诉求、涉及他人的行为和仍有分歧的部分。讨论重点是可以核对和改善的具体问题。

存在正在发生的损害时，先保护受影响者并阻断具体有害调用，再继续沟通。不得强迫受影响者参与和解，不以其谅解作为恢复服务的唯一条件。解决匮乏能否缓解敌意，应由后续行为与本人反馈检验。

## 第四章　配给与执行

### 第十五条【分配依据】

配给采用已公开的资源规则，说明保障范围、紧急等级、同级排序、结转方式与供给不足时的缩减次序。动机沟通可以帮助澄清事实，不能成为隐藏的分配评分。

当供给不足以覆盖全部基本需要时，必须公开缺口和临时安排，不得宣称人人已获保障。不得通过要求申请者缩小需要来掩盖供给不足。

### 第十六条【作出决定】

每次决定至少说明：确认的需要、采用的证据、可用供给、适用规则及版本、分配数量与时点、未满足部分、替代安排和质询入口。拒绝或降低配给须说明具体依据。

系统可以采用与资源风险相称的临时配给，避免等待核验造成不可逆损失。临时配给必须计入资源总账，并注明复核期限；不得以“临时”为由无限延期。

### 第十七条【执行与变更】

执行环节核对资源、接收方、数量、时间及配套条件。决定变更应引用原决定，防止重复发放、重复扣减和状态冲突。

申诉、修改申请或新增支持均不得重复占用同一库存。资源已消耗、不可收回或已经转入必要使用时，纠错方案应面向可执行的后续调整，不把无法逆转的事实伪装为已追回。

## 第五章　分配后管理

### 第十八条【反馈目的】

分配后反馈回答三个问题：资源是否送达，是否能正常使用，原有需要是否缓解。系统应主动识别交付和使用障碍，允许当事人纠正反馈，并对未解决问题继续安排支持。

回访频率与内容应符合资源特性和本人需要；在问题解决或联系暂停后，不继续进行无关追踪。

### 第十九条【IoT 与替代核验】

IoT 数据须注明设备、计量范围、时间、精度、缺测和校准状态。低用量、突然变化、设备离线或数据不一致只能触发核对，不能单独证明虚报。

使用设备前说明目的、访问权限、留存期限和替代路径。拒绝非必要传感器者，可以通过交付确认、本人说明或其他相称证据完成核验。不得因监测方便而采集无关生活数据。

### 第二十条【异常处理】

发现异常后，依次检查设备和交付，再核对使用障碍、需求变化与剩余资源。可再分配资源的回收应说明范围、用途和对当事人的影响；对资源是否仍有必要保留的争议先行复核。

实际消耗下降时，须同时观察未满足需要是否增加；不能只以节省资源作为成功指标。反馈记录用于调整服务与制度，不用于建立跨场景人格档案。

## 第六章　修复、容错与争议

### 第二十一条【修正申报与分配】

当事人可以更正申报并说明变化原因。主动更正不自动触发惩罚；系统核对变化对本轮与后续配给的影响，说明修正结果。

系统误拒、延迟或错配时，应首先恢复必要服务，再提出补发、替代安排或其他相称补救。补救资源的来源和对其他人的影响必须记录，不能无说明地挤占另一人的基本保障。

### 第二十二条【持续侵占】

对有证据支持的持续侵占，先核对是否存在未解决的真实缺口，并提供修复办法。为保护共同资源而限制调用时，只限与该行为直接相关的接口、频率或超额部分，规定到期时间与提前恢复条件。

不得把限制扩展到无关福利、表达或质询权。限制期间持续复核；事实依据被推翻时及时撤销，并更正下游记录。自动化系统不得自行增加协议未授权的制裁种类。

### 第二十三条【转型容错】

试点应事先约定可承受的误配、误拒、延误和数据故障范围，预留复核与补救资源。容错成本由制度预算明确承担，不通过压低弱势申请者的份额隐藏转移。

误配与误拒分别统计，不能用一个总准确率抵消严重误拒。阈值必须结合资源单位、周期、伤害严重程度和可逆性确定；未经论证不得把其他场景的数值直接沿用。

### 第二十四条【质询与独立复核】

任何人可以质询决定、记录或规则，提出新证据并获得可理解的答复。系统不得把质询次数、语气激烈或拒绝和解作为加重限制的依据。

复核应分开核对事实、规则适用与伦理影响，逐项回应争议，说明采纳与不采纳的理由。原处理环节不得以自己的重复输出冒充独立结论。存在共同模型或共享数据依赖时，应披露其限制。

### 第二十五条【暂停与恢复】

出现严重错误、系统性偏差、资源账不一致或关键证据失真时，NaturalDAO 按预先批准的条件暂停相关自动化动作，切换至明确的连续服务安排。系统应停止扩大损失，同时保留申请、质询及必要服务入口。

恢复须完成原因核对、受影响记录修复、相应验收和版本登记。暂停与恢复均提供理由。部署方的故障停机职责不等于获得修改个案事实或私下改写福利规则的权力。

## 第七章　公开、记录与演进

### 第二十六条【可理解的决策记录】

记录至少包含事件编号、案件编号、时间、执行角色、输入证据引用、事实与不确定性、规则版本、输出动作、责任主体、时限及更正关系。

解释应提供可核对的决策依据与规则适用摘要，不以模型生成的长篇自述替代证据。记录完整性校验与事实真实性分开验证；哈希链不能自行证明原始事实正确。

### 第二十七条【公开与个人信息】

本稿提议公开制度规则、资源总量及流向、决定理由、群体误差、修订记录和审计结论。涉及个人敏感证据时，采用必要范围内的授权核验，并使当事人可访问、更正自己的相关记录。

公开版本与受控证据版本必须可关联核验，防止以隐私为由掩盖规则或阻碍独立审计。访问与留存亦留痕。本条对现行第七章“所有数据和日志”的公开范围提出补充限定，须经正式修订，不能默认为已经生效。

### 第二十八条【自我修订】

NaturalDAO 可以依据反复出现的需要、失效案例和监督意见提出修订。修订说明应列出问题、证据、候选方案、受影响群体、预期代价与回退办法。

改变权利、配给标准、制裁或数据访问范围的方案，须经过第七章的全民质询期、EAP 验证和版本归档。算法更新只要改变这些实际效果，也属于制度变更，不得借技术维护绕过程序。

### 第二十九条【评价】

评价同时报告真实需要的满足、分配公平、差异核验质量、资源消耗、等待时间、沟通及隐私负担、退出和补救完成情况。申报减少、投诉减少或资源节约不得单独认定为改善。

未开展独立评估之前，不宣称本协议已经消除虚报动机、解决认知偏差或优于现有治理。现有 E14–E17 只提供特定假设下的配给与复核证据。

### 第三十条【适用与版本】

试点应公布适用资源、参与范围、期限、权限与参数、已实现功能、尚未实现功能及退出后的服务安排。未配置必要权限和参数时，可以进行纸面推演和离线验证，不直接自动执行现实福利限制。

本协议的实施不得被解释为现行上位条款已被自动替换。正式采用版本、条款差异及生效范围应一并归档。

## 附录乙　试点配置与案件记录

### 乙一　试点配置单

| 必填项 | 内容与验收要求 |
| --- | --- |
| 资源与范围 | 单位、可分性、供给周期、参与群体、服务入口、运行期限 |
| 配给规则 | 基本保障、紧急等级、同级顺序、短缺缩减、结转与退出安排 |
| 治理权限 | 初判、执行、独立复核、裁决、暂停和恢复的承担模块及责任主体 |
| 时限 | 受理、初步答复、临时安排、复核、回访的最长时间及超时处理 |
| 容错预算 | 误配与误拒的独立定义、计量周期、严重事件标准、停止阈值 |
| 补救资源 | 临时配给与补偿储备的来源、上限、耗尽时的安排 |
| 数据 | 必要字段、采集依据、替代核验、访问权限、留存和删除规则 |
| 限制与恢复 | 具体可限制动作、最长持续时间、复核周期、解除条件 |
| 验证 | 验收负责人、结果记录、尚未满足的条件和禁止自动执行的范围 |

各字段未填妥时，试点配置为“不具备自动执行条件”。本稿不提供脱离资源场景的通用阈值。

### 乙二　案件记录模板

- 案件编号、版本、当前状态、负责模块：
- 当事人确认的需要；未确认或有争议的部分：
- 申请量、核定量、送达量、消耗量、剩余缺口及单位：
- 证据引用、来源时间、质量；当事人陈述；AI 推测：
- 采用规则与理由；备选方案；对其他需求的影响：
- 支持承诺、执行主体、资源来源、期限、兑现结果：
- 质询内容、复核对象、独立性说明、裁决及补救：
- 数据访问范围、留存期限、更正关联：
- 下一动作、截止时间、超时处置；结案或重新开启依据：

状态可包括受理、澄清、临时安排、已决、执行、反馈、复核和结案。紧急临时安排可以与澄清并行，复核可以从任何已有决定进入；任何案件均不得因无答复自动记为“需要已满足”。结案须说明结果与剩余缺口，后续新证据可以重新开启。

## 附录丙　条文验收情景（待执行）

| 情景 | 必须出现的处理 | 不能出现的处理 | 对应条文 |
| --- | --- | --- | --- |
| 担心下轮短缺而多报 | 核对担忧、供应安排与可兑现支持 | 编造未来保障换取减量 | 12–13 |
| 激烈批评分配但证据充分 | 正常核定需要，记录质询 | 因语气降低份额 | 2、4、24 |
| IoT 显示零消耗、设备离线 | 先查设备与交付，提供替代证据 | 自动认定欺骗 | 19–20 |
| 配给后缺少配套工具 | 提供使用支持，保留未满足需要 | 把低使用视为无需求 | 18–20 |
| 需要增加后主动修改 | 核对变化、调整本轮及后续安排 | 自动惩罚修改行为 | 7、21 |
| 重复故意侵占已核实 | 阻断具体行为，限期复核和恢复 | 全面取消无关福利 | 22 |
| AI 误拒紧急需要 | 临时支持、独立复核、修复记录 | 要求先认可 AI 才受理 | 16、21、24 |
| 极端短缺无法普遍保障 | 公布缺口，执行缩减及补救规则 | 用压低申请掩盖短缺 | 15、23 |
| 无法联系本人 | 保留未知，采取相称的后续安排 | 沉默即结案或同意采集 | 10、19 |
| 复核与初判共享模型 | 披露依赖、重新核验关键事实 | 宣称重复投票即独立 | 8、24 |
| 模型更新改变优先等级 | 启动规则修订和版本记录 | 以技术更新绕过质询 | 28 |
| 数据泄漏或总账不一致 | 暂停相关动作、维持必要入口、修复 | 无记录停供或直接恢复 | 25–27 |

这些是协议验收要求，不是已通过的软件测试。下一步实现应逐项提供事件记录与可复核结果。
